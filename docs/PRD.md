## 1. 문제 정의

지금 상태:
- 릴스 협업한 인플루언서가 꽤 쌓였는데, **누가 잘했는지 기억에 의존**한다.
- 성과 링크(게시물 URL)와 인사이트 스크린샷이 카톡/DM/폴더에 흩어져 있다.
- **단가를 매번 다시 물어본다.** 과거에 얼마에 했는지, 지금 얼마 부르는지 추적이 안 된다.
- "이 카테고리에서 예산 300만으로 5명" 같은 요청에 즉답이 안 된다.

핵심 통증은 "기록이 없다"가 아니라 **"기록이 비교 가능한 형태가 아니다"** 입니다. 그래서 이 프로젝트의 본질은 아카이브 저장소가 아니라 **비교·정렬 가능한 지표 레이어**를 만드는 것입니다.

## 2. 목표 / 비목표

### 목표
1. 인플루언서 1명 = 페이지 1개. 프로필·단가·협업 이력·콘텐츠 성과가 한 화면에.
2. 모든 협업 릴스를 **CPV / 저장률 / 팔로워 대비 조회수 배수**로 한 테이블에서 정렬 가능.
3. 단가를 **시점별 이력**으로 관리 (2024년 80만 → 2026년 150만 같은 변화가 보이게).
4. 후보 리스트를 담아서 **예산 합계 + 공유 링크**로 뽑기.

### 비목표 (이번엔 안 함)
- 인플루언서 검색/발굴(디스커버리). 우리가 이미 아는 사람만 관리.
- 자동 스크래핑/크롤링. 인스타 약관 리스크 + 금방 깨짐.
- 계약서 생성, 전자서명, 세금계산서 발행.
- 인플루언서와의 메시지 커뮤니케이션 기능 (DM/메일은 기존 채널 유지).
- 실시간 지표 동기화.

## 3. 핵심 사용자 시나리오

1. **다음 캠페인 후보 뽑기** — 카테고리=뷰티, 팔로워 3만~10만, 평균 CPV 30원 이하, 재협업 의향 ★4↑ 필터 → 8명 → 후보 리스트에 담기 → 예산 합계 확인 → 공유 링크 생성.
2. **협업 직후 성과 기록** — 릴스 URL 붙이고 조회수/좋아요/저장/공유 입력 → CPV·참여율 자동 계산 → 등급 자동 부여.
3. **재협업 판단** — 인플루언서 상세에서 과거 3건의 CPV 추이 + 단가 인상폭 비교 → "단가는 2배 올랐는데 CPV는 3배 나빠짐" 같은 판단.
4. **단가 문의 대응** — 이름 검색 → 최신 유효 단가 카드 확인.

### 4.6 content_metric — 성과 스냅샷 (content : N)

릴스는 업로드 후 2~4주까지 조회수가 계속 올라갑니다. **단일 값으로 저장하면 24시간 뒤 기록한 A와 한 달 뒤 기록한 B를 공정하게 비교할 수 없습니다.** 그래서 스냅샷 테이블로 분리합니다.

### 4.7 파생 지표 (DB view로 계산, 저장하지 않음)

| 지표 | 공식 | 왜 필요한가 |
|------|------|------|
| **CPV** | total_cost / views | 가장 직관적인 가성비. 원 단위 |
| **CPE** | total_cost / (likes+comments+saves+shares) | 인터랙션 기준 효율 |
| CPM | total_cost / views × 1000 | 광고 대비 벤치마크 |
| **참여율** | (likes+comments+saves+shares) / views | reach 있으면 reach 기준으로 (더 정확) |
| **뷰 배수** | views / follower_count | ⭐ **릴스 평가의 핵심.** 1배 미만은 팔로워에게만 도달 = 확산 실패. 3배↑ = 알고리즘 탄 것 |
| 저장률 | saves / views | 정보성 콘텐츠 품질 |
| 공유율 | shares / views | 바이럴 잠재력 |
| 팔로워 전환률 | follows_gained / views | |
| 인플루언서 평균값 | 위 지표들의 인플루언서별 median | **평균 대신 중앙값** — 대박 1건에 왜곡되지 않게 |
| 등급 | A/B/C/D | 뷰배수 + CPV 백분위 조합, 기준은 설정에서 조정 가능 |

### 4.8 보조 테이블

## 5. 화면 설계

### 5.1 대시보드
- KPI 카드: 총 인플루언서 수 / 총 협업 건 / 누적 지출 / 누적 조회수 / 평균 CPV
- 기간 필터 (최근 3개월 기본)
- 카테고리별 평균 CPV 막대
- 최근 협업 5건 + 성과 상위 5건
- 입력 누락 알림: "성과 미입력 협업 3건", "업로드 30일 지났는데 final 스냅샷 없음 5건" ← **데이터 썩는 걸 막는 장치**

### 5.2 인플루언서 풀 (메인)
- **테이블 뷰**: 썸네일, 이름/핸들, 팔로워, 티어, 카테고리, 최신 단가, 협업수, 평균 뷰배수, 평균 CPV, 재협업 의향, 상태
- **갤러리 뷰**: 카드형 (제안 자료 만들 때)
- 필터: 카테고리, 태그, 팔로워 범위, 단가 범위, CPV 범위, 뷰배수, 재협업 의향, 상태, 지역, 소속사 유무, 협업 유무
- **저장된 필터**(뷰) — "뷰티 마이크로 가성비" 같은 걸 재사용
- 정렬: 모든 숫자 컬럼
- 다중 선택 → 후보 리스트에 담기 / 비교하기 / CSV 내보내기

### 5.3 인플루언서 상세
- 헤더: 아바타, 이름, 핸들+원본링크, 팔로워, 티어, 카테고리 칩, 상태, 재협업 의향
- 요약 스탯: 협업 N회, 총 지출, 누적 조회수, 중앙 CPV, 중앙 뷰배수
- **단가 카드**: 현재 유효 단가 항목별 + 이력 타임라인(접기)
- **협업 히스토리**: 캠페인별 카드 → 콘텐츠 썸네일 + 지표 + 원본 링크
- **성과 차트**: 협업 시점별 CPV/뷰배수 추이 (단가 인상 시점 표시) + 팔로워 추이
- 컨택 정보 (권한별 마스킹)
- 내부 메모 (마크다운, 수정 이력)
- 첨부파일

### 5.4 콘텐츠 성과 목록
> "릴스 성과 싹 볼 수 있는" 화면. 모든 협업 콘텐츠를 인플루언서 무관하게 한 테이블에.

- 썸네일, 인플루언서, 캠페인, 게시일, 유형, 조회수, 좋아요, 저장, 공유, 참여율, 뷰배수, 비용, CPV, 등급, 원본 링크
- 정렬/필터, 링크 새 창, 인사이트 스크린샷 라이트박스
- **성과 분포 산점도** (X=팔로워, Y=조회수, 대각선=1배/3배 기준선, 점=콘텐츠) — 저평가된 인플루언서를 눈으로 찾는 뷰

### 5.5 캠페인 상세
- 예산 vs 실지출, 목표 vs 실제 총 조회수, 캠페인 평균 CPV
- 참여 인플루언서 성과 랭킹
- 상태별 진행 보드

### 5.6 비교 뷰
- 최대 5명 컬럼 나란히: 팔로워, 단가, 협업수, CPV, 뷰배수, 참여율, 저장률, 평점, 대표 콘텐츠 3건
- 지표별 최고값 하이라이트

### 5.7 후보 리스트 & 공유
- 담기 → 예산 합계(부가세 옵션) / 예상 총 도달(과거 중앙 조회수 합) / 예상 CPV
- 공유 링크 생성 옵션: **단가 숨김 / 단가 그대로 / 마크업 % 적용**, 메모 숨김(기본), 만료일, 비밀번호
- 공유 페이지는 읽기 전용 + 내부 메모/컨택/평점 절대 미노출

### 5.8 입력
- **빠른 등록**: 인플루언서 최소 필드(이름, 핸들, 플랫폼, 팔로워)만으로 생성
- **성과 입력 폼**: URL + 지표 + 스냅샷 라벨 + 스크린샷 드래그앤드롭
- CSV 임포트: 컬럼 매핑 UI + 프리뷰 + 중복(핸들 기준) 병합/스킵 선택
- 인스타 URL 붙이면 oEmbed로 썸네일/캡션 정도만 보조 채우기 (지표는 수동)

## 6. 권한

| 역할 | 권한 |
|------|------|
| owner | 전체 + 설정 + 멤버 관리 + 삭제 |
| editor | 조회 + 등록/수정, 컨택·단가 조회 가능 |
| viewer | 조회만, 컨택 마스킹, 내부 메모 비노출 |
| share (링크) | 지정 selection만, 단가 정책 적용, 메모/컨택/평점 전부 비노출 |

## 7. 비기능 요구사항

- **개인정보**: 연락처·실명은 컬럼 단위 암호화 + viewer 마스킹. 계좌번호는 **저장하지 않음** (보관 필요성 < 유출 리스크. 정산은 기존 채널 유지)
- **데이터 출처 표시**: 모든 지표에 `source` 표기. 본인 전달 수치와 스크린샷 확인 수치를 시각적으로 구분
- **인스타 정책**: 스크래핑 없음. 공개 임베드(oEmbed)와 수동 입력만
- **이미지**: 인스타 CDN 핫링크 금지(만료됨) → 업로드해서 자체 스토리지 보관
- 반응형 (현장에서 폰으로 조회), 다크모드
- 감사 로그, 소프트 삭제
- 백업: Supabase 일일 백업 + CSV 전체 내보내기 버튼 (락인 방지)

## 8. 개발 계획

### Phase 0 — 스키마 & 임포트 (3~4일)
Supabase 스키마, RLS, 파생지표 view, CSV 임포터, 기존 아카이브 1회 마이그레이션.
→ **UI 전에 데이터를 먼저 넣습니다.** 실제 데이터를 보면 필드가 반드시 바뀌므로.

### Phase 1 — MVP (1.5~2주)
인플루언서 풀 테이블 + 필터/정렬 · 상세 페이지 · 단가 카드/이력 · 콘텐츠 성과 목록 · 입력 폼 · 로그인.
**이 시점에 이미 실사용 가능.**

### Phase 2 — 의사결정 도구 (1~1.5주)
대시보드, 후보 리스트, 공유 링크, 비교 뷰, 차트, 갤러리 뷰.

### Phase 3 — 운영 편의 (이후)
입력 누락 알림, 산점도, 등급 기준 커스터마이즈, 팔로워 추이 자동 스냅샷, 유튜브/틱톡 확장, 팀 멤버 초대.

### 기술 스택 (A5)
| 레이어 | 선택 | 이유 |
|------|------|------|
| 프론트 | Next.js App Router + TypeScript | 서버 컴포넌트로 테이블 필터링을 서버에서 처리 |
| UI | Tailwind + shadcn/ui | 테이블·필터·다이얼로그가 대부분 |
| 테이블 | TanStack Table | 정렬/필터/컬럼 토글 |
| 차트 | Recharts | 추이선·막대·산점도 수준이면 충분 |
| DB/Auth/Storage | Supabase | Postgres view로 파생지표 계산, RLS로 권한, Storage로 스크린샷 |
| 배포 | Vercel | |

**설계 원칙 3개**
1. 파생지표는 **절대 컬럼으로 저장하지 않는다** (view 또는 계산 필드). 기준이 바뀌면 재계산되어야 함.
2. 시간에 따라 변하는 값(단가, 팔로워, 성과)은 **전부 이력 테이블**. 덮어쓰기 금지.
3. 입력 마찰을 최소화한다. 필수 필드는 4개 이하. **안 쓰이는 툴이 되는 원인의 90%는 입력 귀찮음**.

## 10. 확인이 필요한 질문

**꼭 답이 필요한 것**
1. **사용 대상** — 내부용만? 클라이언트에게도 보여줄 계획이 있나요? (공유 링크 우선순위가 바뀝니다)
2. **기존 아카이브 형태** — 스프레드시트/노션/엑셀/흩어짐 중 어디에? 스프레드시트면 컬럼 구조를 보고 스키마를 거기에 맞추겠습니다. 임포터 작업량이 여기서 갈립니다.
3. **성과 지표를 실제로 어디까지 갖고 있나요?** — 조회수·좋아요만? 아니면 저장·공유·도달까지 인사이트 스크린샷을 받아둔 협업이 많나요? (도달 없으면 참여율 기준을 views로 고정)
4. **협업 규모** — 인플루언서 대략 몇 명, 릴스 몇 건인가요? (수십 vs 수백에서 UI 우선순위가 다름)

**있으면 좋은 것**
5. 단가에 물물교환(제품 제공)이 섞인 경우가 많나요? 제품 정가를 비용에 포함해서 CPV를 계산할까요, 현금만 계산할까요?
6. 캠페인/브랜드 단위 묶음이 의미가 있나요, 아니면 그냥 개별 협업의 나열인가요? (의미 없으면 campaign 테이블을 태그로 단순화)
7. 여러 명이 같이 입력하나요, 혼자 쓰나요? (혼자면 권한 시스템을 Phase 3으로 미룸)
8. 유튜브/틱톡 협업도 있나요, 인스타만인가요?
9. 프로모 코드나 UTM 링크로 **매출 전환**을 추적한 적 있나요? 있으면 ROAS 항목을 1차에 넣겠습니다.
