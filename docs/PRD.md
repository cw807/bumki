## 1. 한 장 요약

500명 넘게 쌓인 릴스 협업 이력이 구글 스프레드시트에 흩어져 있고, **성과 수치는 거의 기록되지 않은 상태**입니다.

이 프로젝트는 두 가지를 순서대로 해결합니다.

1. **먼저 명부를 세운다** — 500명을 검색·필터·태그로 즉시 찾을 수 있게. 단가는 시점별 이력으로.
2. **그 다음 성과를 쌓는다** — 링크만 있는 과거 협업의 공개 수치를 빠르게 채워 넣는 전용 화면(백필 큐)을 만들고, 앞으로의 협업은 입력이 습관이 되게.

**핵심 판단: 이번 1차 목표는 성과 분석이 아니라 "찾을 수 있는 명부"입니다.** 지표가 없는 상태에서 CPV 대시보드를 먼저 만들면 빈 화면만 봅니다.

## 2. 배경 및 문제

### 지금 상태
- 협업한 인플루언서 **500명 이상**, 자료는 **구글 스프레드시트**
- 릴스 링크는 모아뒀지만 **조회수·좋아요 같은 성과 수치는 거의 없음**
- 단가를 매번 다시 물어본다. 과거에 얼마였는지 추적 불가
- "이 카테고리에서 예산 300만으로 5명" 같은 요청에 즉답이 안 된다

### 진단
문제는 "기록이 없다"가 아니라 **"기록이 찾을 수 있고 비교할 수 있는 형태가 아니다"** 입니다.

### 시트로 계속 못 가는 이유
| 한계 | 왜 문제인가 |
|---|---|
| 행 500개 넘으면 스크롤 지옥 | 조건 조합 검색이 사실상 불가 |
| 단가는 값이 하나만 들어간다 | "2024년 80만 → 2026년 150만"이 안 남음. 덮어쓰면 이력이 사라짐 |
| 이미지·스크린샷을 못 담는다 | 인사이트 증빙이 시트 밖 폴더에 흩어짐 |
| 계산 컬럼이 깨진다 | CPV·참여율을 수식으로 넣으면 행 추가·복붙에서 무너짐 |
| 링크가 죽어도 모른다 | 게시물 삭제 감지 불가 |

**단, 시트를 버리진 않습니다.** 시트는 최초 이관 소스이자 백업 내보내기 형식으로 유지합니다.

## 3. 전제 조건

| # | 항목 | 확정 내용 |
|---|---|---|
| 1 | 사용 대상 | **미정** → 1차는 내부용(로그인 필수)으로 구축. 외부 공유는 스키마에 자리만 만들어두고 Phase 3에서 켠다 |

| 3 | 성과 데이터 | **거의 없음** (게시물 링크 32건 확인) → 백필 워크플로우가 핵심. 파생지표 화면은 만들되 빈 상태 설계 필수 |
| 4 | 규모 | **500명 이상** → 검색·필터·벌크 편집이 1순위, 개별 상세 페이지는 2순위 |
| 5 | 협업 형태 | **유가 협업** (시딩 비용 20~50만, 피드 10~150만, 릴스 15~300만 수준). 제품 제공이 함께 붙는다 |
| 6 | 지표 수집 | **Apify 계정 보유**. 단 팔로워는 시트에 이미 있으므로 **조회수 등 성과 수치 수집에만 사용** |
| 7 | 주 플랫폼 | 인스타그램 릴스·피드 중심, 유튜브 쇼츠·틱톡은 동일 스키마로 확장 |
| 8 | 기술 스택 | Next.js + TypeScript + Supabase(Postgres) + Vercel |

### 3.1 확인된 실제 시트 구조

소스는 **두 종류**이고, 성격이 완전히 다릅니다.

#### (1) IMC MKT PLAN 시트 — **1차 소스**

예: `26FW CGP IMC MKT PLAN` (23MB). 시즌 × 브랜드 단위로 존재하는 **실제 관리 대장**입니다. 탭이 여러 개이고, 각 탭이 협업 라이프사이클의 다른 단계를 담습니다.

| 탭 성격 | 주요 컬럼 | 실측 |
|---|---|---|
| **단가·컨택 후보** | 성별 · 인스타그램 ID · IG 팔로워 · 인스타그램 주소 · 진행현황 · **피드 / 2차 활용비** · **릴스 / 2차 활용비** · 이메일 · 비고 | 117명 (피드 단가 42명, 릴스 단가 28명, 이메일 16명) |
| **컨택 파이프라인** | 성별 · 인스타그램 ID · IG 팔로워 · 주소 · 진행현황 · 진행 콘텐츠 · 이미지 전달 일정 · 착용 제품 · 업로드 일 · 업로드 링크 · 파트너십 광고 코드 | 183명 (링크 0건 — 진행 전 단계) |
| **시딩 진행 (제품 단위)** | 배송지 · 진행현황 · 성별 · 인스타아이디 · 팔로워 · 링크 · 이메일 · **비용** · 착장 수 · 업로드 일정 · 바코드 · 품번 · 제품 · 착용 컬러 · 사이즈 · **업로드 링크** · **2차 활용 기간** · **파트너쉽 코드** · 비고 | 18명 / 86행, 링크 6명 |
| **시딩 진행 (SKU판)** | 위와 유사 + SKU · 이미지 전달 경로 | 28명 / 87행, 링크 1명 |
| 모델 캐스팅 | 성별 · 이미지 · 인스타그램 · 비용 · 컨택 · 비고 | 별도 관리 |

시트 전체에서 게시물 링크는 **32건** 확인됩니다. 즉 링크는 "진행 완료된 건만" 붙어 있습니다.

#### (2) 구글 폼 응답 시트 — **보조 소스**

예: `[26 FALL / MU] kiimuir 콘텐츠 협업(응답)`(33행), `CGP 26 Summer : 인스타그램 릴스 (토마토/6Style)(응답)`(18행). 신청 접수·배송 정보 수집용입니다. 배송지·사이즈·신체 스펙은 여기에만 있지만, **단가·성과·링크는 없습니다.** 계열별로 컬럼명이 다릅니다(`성함`/`이름`, 신체정보 1칸/분리, 제품 6세트 반복 컬럼).

#### 여기서 도출되는 제약

| 발견 | 영향 |
|---|---|
| **단가가 실존한다** | `150/30` = 피드 150만 / 2차 활용비 30만. **만원 단위.** `rate_card`를 1차에 제대로 만든다 |
| **단가 표기가 매우 자유롭다** | `150/30` · `300 / 50` · `70/` · `100/50(1개월)` · `40/2차 활용 별도` · `착장 7(2차활용포함)` · `15~20` · `확인 중` · `-` → **파서 + 예외 수동 처리 큐**가 임포터의 최대 난이도 지점 |
| **팔로워가 100% 채워져 있다** | 86/86, 205/205, 117/117. 팔로워는 스크래핑할 필요가 없다 → Apify 용도를 **성과 수치로 한정** |
| 팔로워 표기 혼재 | `6,629` / `5318` / `232000` → 콤마 제거·정수 변환 |
| **파트너십 광고 코드가 있다** | `adcode-Q9jTBBegvzTszhPI-…`. 브랜드 광고 관리자에서 **실제 도달·노출을 조회할 수 있는 경로** → 인사이트 스크린샷 없이도 성과 확보 가능 (5.4) |
| **2차 활용 기간을 이미 관리 중** | `1개월` 등 → `usage_rights` / `usage_rights_months`를 1차로 승격 |
| 제품이 행 단위로 펼쳐져 있다 | 1명당 평균 4.8행(바코드·품번·제품·컬러·사이즈) → `collab_product` 하위 행으로 정규화, 인물 단위로 접어서 표시 |
| 진행현황 파이프라인이 실존 | `컨택 전`(68) · `컨탠 완료`(69, 오타) · `업로드 완료` · `입금일정 조율` → status enum으로 채택, **오타·표기 통일 필요** |
| 링크가 32건뿐 | 진행 완료분만 존재. 나머지는 5.1 자동 매칭 또는 수동 |
| 시트 1개가 한 시즌 × 한 브랜드 | 500명+는 이런 시트 여러 개의 합. **시즌 시트마다 어댑터를 재사용**하도록 설계 |

## 4. 목표와 범위

### 목표
1. 500명 명부에서 조건 조합으로 **10초 안에** 후보를 찾는다
2. 인플루언서 1명 = 페이지 1개. 프로필·단가 이력·협업 이력·릴스 링크가 한 화면
3. 성과 수치를 **건당 20초 안에** 입력할 수 있다 (이 마찰이 프로젝트 성패를 가른다)
4. 지표가 쌓이면 CPV·뷰배수로 정렬해 재협업 판단 근거가 된다

### 하지 않을 것
- 인플루언서 발굴/검색(디스커버리) — 우리가 아는 사람만 관리
- 인스타 스크래핑·크롤링 — 약관 리스크 + 금방 깨짐
- 계약서 생성, 전자서명, 세금계산서 발행
- 인플루언서와의 메시지 기능 — DM·메일은 기존 채널 유지
- 실시간 지표 동기화

## 5. 핵심 전략 — 성과를 어떻게 쌓을 것인가

응답 시트에는 **게시물 URL 자체가 없습니다.** 즉 문제는 "수치가 없다"가 아니라 "링크부터 없다"입니다. 그래서 전략이 2단이 됩니다.

### 5.1 링크 자동 매칭 (선행 단계)

응답 시트에 핸들과 타임스탬프는 전부 있습니다. 이 두 개로 게시물을 역추적합니다.

```
응답 시트의 핸들 + 타임스탬프
  → Apify로 해당 계정의 릴스·피드 수집 (타임스탬프 기준 +2~4주 윈도우)
  → 캡션에 브랜드 멘션(@kiimuir / @codegraphy) 또는 paidPartnership 플래그
  → 해당 협업 건에 자동 매칭 → 사람은 검수만
```

- 매칭 신뢰도를 3단계로 표기: 확실(멘션+기간 일치) / 추정(기간만 일치) / 실패
- 실패 건만 수동 입력 큐로 넘김 — 500건을 손으로 모으는 것보다 훨씬 적은 작업
- 브랜드 계정에 태그된 게시물을 역방향으로 긁는 경로도 보조로 사용

**한계:** 100% 매칭은 불가능합니다. 협업자가 멘션을 안 했거나 이미 삭제한 건은 놓칩니다. 그래서 **앞으로의 협업은 폼에 "업로드 링크" 컬럼을 추가하는 것이 근본 해결책**입니다 (5.3).

### 5.2 성과 백필 큐

링크가 확보된 콘텐츠 중 수치가 비어 있는 것만 한 줄씩 띄워주는 전용 화면입니다. Apify로 조회수·좋아요·댓글은 자동 수집되므로, 이 화면은 **인사이트 스크린샷이 있는 건의 도달·저장·공유를 채우는 용도**가 주가 됩니다.

```
[릴스 썸네일]  @handle · 2025-03-12 · A브랜드
링크 열기 ↗   조회수 [        ]  좋아요 [        ]  댓글 [        ]
                              [건너뛰기]  [저장하고 다음 →]
```

- 링크를 새 탭에서 열고 숫자만 입력 → Enter → 다음 건
- 진행률 표시 ("412건 중 178건 완료")
- Apify가 채운 값은 미리 채워진 상태로 보여주고, 사람은 이상값만 고침

### 5.3 앞으로의 협업은 입력이 습관이 되게

**폼을 먼저 고치는 것이 가장 값싼 개선입니다.** 응답 시트에 다음 컬럼을 추가하면 이후 협업은 백필이 아예 필요 없어집니다.

| 추가할 폼 항목 | 이유 |
|---|---|
| **업로드 게시물 링크** | 지금 가장 큰 공백. 이것만 받으면 링크 매칭 로직이 불필요해짐 |
| 업로드 완료일 | 스냅샷 기준일 |
| 인사이트 스크린샷 업로드 | 도달·저장·공유 확보 |

- 협업 등록 시 업로드 예정일 기록 → 업로드 후 3일/30일에 **입력 리마인더**
- 대시보드에 "성과 미입력 N건" 상시 노출
- 필수 필드는 4개 이하로 유지

### 5.4 파트너십 광고 코드 — 가장 신뢰도 높은 성과 경로

시딩 탭에 `파트너쉽 코드`(`adcode-…`)가 기록되어 있습니다. 인스타 브랜디드 콘텐츠 파트너십이 걸린 게시물은 **브랜드 광고 관리자에서 도달·노출·지출을 직접 조회할 수 있습니다.**

| 경로 | 얻는 값 | 신뢰도 |
|---|---|---|
| **파트너십 광고 코드** | 도달 · 노출 · 지출 (+ 광고 집행 시 성과) | **가장 높음** — 플랫폼 원본 |
| 인사이트 스크린샷 | 도달 · 저장 · 공유 · 시청시간 | 높음 (상대가 줘야 함) |
| Apify 공개 수집 | 조회수 · 좋아요 · 댓글 | 보통 |
| 본인 전달 수치 | 자유 | 낮음 |

코드가 있는 건은 이 경로를 1순위로 씁니다. `content_metric.source`에 `파트너십코드` 항목을 추가합니다.

## 6. 사용 시나리오

### 시나리오 A — 후보 뽑기 (가장 자주)
1. 명부에서 필터: 카테고리=뷰티, 팔로워 3만~10만, 최신 단가 ≤120만, 재협업 의향=무조건
2. 12명 → 다중 선택 → 후보 리스트에 담기
3. 예산 합계 확인 → 공유용으로 내보내기

### 시나리오 B — 협업 직후 기록
1. 인플루언서 검색 → 협업 추가 (캠페인, 확정 단가, 제공 제품)
2. 릴스 URL 붙이기 → 3일 후 리마인더 → 수치 입력
3. CPV·뷰배수 자동 계산, 등급 자동 부여

### 시나리오 C — 재협업 판단
1. 인플루언서 상세 → 과거 3건 CPV 추이 + 단가 인상 시점 겹쳐보기
2. "단가는 2배 올랐는데 뷰배수는 절반" → 조건부로 재협상

### 시나리오 D — 단가 문의 대응
이름 검색 → 최신 유효 단가 카드 확인 (30초)

### 7.2 단가 `rate_card` — 인플루언서 : N (시점별 이력)

단가는 숫자 하나가 아니라 **항목 × 시점**입니다. 인플루언서 테이블 컬럼으로 넣으면 반드시 후회합니다.

**임포터 파싱 규칙** — 시트의 `피드 / 2차 활용비`, `릴스 / 2차 활용비` 컬럼은 표기가 자유로워서 규칙 + 예외 처리가 필요합니다. 단위는 **만원**입니다.

| 시트 표기 | 해석 |
|---|---|
| `150/30` | 피드 150만 + 2차 활용비 30만 |
| `300 / 50` | 공백 포함. 동일 해석 |
| `70/` | 피드 70만, 2차 활용비 미정 |
| `100/50(1개월)` | + `usage_rights_months = 1` |
| `40/2차 활용 별도` | 2차 활용비를 `별도협의`로 표기 |
| `착장 7(2차활용포함)` | 착장 단위 과금 7만, 2차 활용 포함 |
| `15~20` | 범위 제시 → `amount_min` / `amount_max` |
| `확인 중`, `-`, 공백 | 미확보. **예외 큐로 보내 사람이 판단** |

→ 파싱 실패분은 버리지 않고 **원문을 `source_note`에 그대로 보존**하고 예외 큐에 넣습니다. 자동 해석을 억지로 밀어넣는 것보다 안전합니다.

| 필드 | 설명 | 단계 |
|---|---|:--:|
| `deliverable_type` | 릴스 / 릴스+스토리 / 스토리단독 / 피드 / 쇼츠 / 라이브 / 방문형 | 1차 |

## 8. 지표 정의

파생 지표는 **컬럼으로 저장하지 않고 DB view로 계산**합니다. 기준이 바뀌면 전체가 재계산되어야 하기 때문입니다.

| 지표 | 공식 | 의미 |
|---|---|---|
| **뷰 배수** | `views / follower_count` | **릴스 평가의 핵심.** 1배 미만이면 팔로워에게만 도달(확산 실패), 3배 이상이면 알고리즘을 탔다는 뜻 |
| **CPV** | `total_cost / views` | 가장 직관적인 가성비 (원/뷰). 분자는 현금 비용 + 제품 원가 |
| CPE | `total_cost / (likes+comments+saves+shares)` | 인터랙션 기준 효율 |
| CPM | `total_cost / views × 1000` | 광고 대비 벤치마크 |
| 참여율 | `(likes+comments) / views` | 도달 데이터 있으면 도달 기준이 더 정확 |
| 저장률 | `saves / views` | 정보성 콘텐츠 품질 |
| 공유율 | `shares / views` | 바이럴 잠재력 |
| 인플루언서 대표값 | 위 지표들의 **중앙값** | 평균은 대박 1건에 왜곡됨 |
| 등급 | A / B / C / D | 뷰배수 + CPV 백분위 조합. 기준은 설정에서 조정 가능 |

**팔로워 대비 뷰 배수를 1차 정렬 기준으로 권장합니다.** 조회수 절대값은 팔로워 많은 사람이 무조건 이기지만, 뷰 배수는 "이 사람 콘텐츠가 실제로 퍼지는가"를 봅니다. 마이크로 인플루언서의 가성비가 여기서 드러납니다.

최대 5명 나란히: 팔로워, 단가, 협업수, CPV, 뷰배수, 참여율, 평점, 대표 콘텐츠 3건. 지표별 최고값 하이라이트

### 9.8 입력
- **빠른 등록**: 이름·핸들·플랫폼·팔로워 4개만으로 생성
- **CSV 임포트**: 컬럼 매핑 UI + 프리뷰 + 핸들 기준 중복 병합/스킵
- 인스타 URL 붙이면 oEmbed로 썸네일·캡션 보조 채우기 (지표는 수동)

### 설계 원칙 3가지
1. **파생 지표는 컬럼으로 저장하지 않는다.** view 또는 계산 필드로. 기준이 바뀌면 재계산돼야 한다

## 11. 권한 및 보안

| 역할 | 권한 |
|---|---|
| owner | 전체 + 설정 + 멤버 관리 + 삭제 |
| editor | 조회 + 등록/수정, 단가·컨택 조회 가능 |
| viewer | 조회만. 컨택 마스킹, 내부 메모 비노출 |
| 공유 링크 | 지정된 후보 리스트만. 단가 정책 적용, 메모·컨택·평점 전부 비노출 |

- 연락처·실명은 **컬럼 단위 암호화**, viewer에게 마스킹
- **계좌번호·상세주소·정확한 신체정보는 저장하지 않음.** 응답 시트에는 있지만 배송·착장 목적으로 수집된 것이라, 아카이브로 옮기면 수집 목적을 넘어선다. 필요한 만큼만(지역, 사이즈 범위) 가공해서 저장
- 공유 링크에는 개인정보를 일절 포함하지 않음
- **Apify 사용 범위를 아카이브 대상으로 한정.** 우리가 협업한 계정의 공개 게시물만 조회하고, 무제한 크롤링은 하지 않음. 스크래핑은 플랫폼 약관 이슈가 있으므로 수집 항목을 최소화한다
- 이미지는 자체 스토리지에 업로드 보관 (인스타 CDN 링크는 만료됨)
- 모든 지표에 `source` 표기 — 본인이 전달한 수치와 스크린샷 확인 수치를 시각적으로 구분
- 소프트 삭제, 변경 이력, 일일 백업 + **CSV 전체 내보내기** (락인 방지)

## 13. 다음 확인 사항

**Phase 0 착수 전에 필요합니다**

1. **IMC PLAN 시트 전체 목록** — `26FW CGP IMC MKT PLAN` 하나를 확인했습니다. 브랜드(코드그라피·키뮤어) × 시즌으로 몇 개가 더 있나요? 이게 곧 임포터 작업량입니다. 드라이브에서 `[키뮤어] 2026 IMC PLAN`, `■코드그라피_26FW_진행현황판■`, `■키뮤어_27SS_진행현황판■` 등도 보였는데 같은 구조인지 확인이 필요합니다.
2. **단가 단위 확인** — `150/30`을 "피드 150만 / 2차 활용비 30만"으로 해석했습니다. 맞나요? `착장 7`은 착장당 7만으로 봤습니다.
3. **파트너십 광고 코드로 성과를 조회할 수 있나요?** 브랜드 광고 관리자 접근 권한이 있으면 도달·노출을 플랫폼 원본으로 가져올 수 있습니다. 이게 되면 인사이트 스크린샷을 받을 필요가 크게 줄어듭니다.
4. **제품 원가표** — CPV 분자에 제품 원가를 포함하려면 품번↔가격 표가 필요합니다. 없으면 현금 비용만으로 계산합니다(그것도 충분히 유효합니다).

**있으면 좋습니다**

5. 시트에 **업로드 링크가 32건뿐**입니다. 나머지 협업의 링크는 다른 곳에 있나요, 아니면 애초에 기록을 안 하신 건가요? 후자라면 5.1 자동 매칭으로 갑니다.
6. 진행현황 값에 `컨탠 완료`(오타) 같은 표기 혼재가 있습니다. 정규화할 표준 값 목록을 정해주시면 그걸로 통일하겠습니다. 제안: `컨택전 / 컨택완료 / 협의중 / 확정 / 배송완료 / 업로드완료 / 정산완료 / 취소`
7. 브랜드가 코드그라피·키뮤어 둘인가요, 더 있나요? 캠페인 파싱 규칙에 반영합니다.
8. 여러 명이 같이 입력하나요, 혼자 쓰나요? 혼자면 권한 시스템을 Phase 4로 미루겠습니다.
9. `릴스크리에이터` 발굴 자동화와 이 사이트를 붙일까요? 발굴 후보 → 아카이브 등록 → 성과 → 발굴 기준 보정으로 순환됩니다. 참고로 현재 발굴 쪽은 추천 0명입니다(`MIN_MEDIAN_VIEWS 10000` + `MIN_SCORE 70`이 동시에 걸려 전원 컷).
10. 프로모 코드나 UTM으로 **매출 전환**을 추적한 적이 있나요? 있으면 ROAS를 지표에 넣겠습니다.
