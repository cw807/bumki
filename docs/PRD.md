## 1. 한 장 요약

500명 넘게 쌓인 릴스 협업 이력이 구글 스프레드시트에 흩어져 있고, **성과 수치는 거의 기록되지 않은 상태**입니다.

이 프로젝트는 두 가지를 순서대로 해결합니다.

1. **먼저 명부를 세운다** — 500명을 검색·필터·태그로 즉시 찾을 수 있게. 단가는 시점별 이력으로.
2. **그 다음 성과를 쌓는다** — 링크만 있는 과거 협업의 공개 수치를 빠르게 채워 넣는 전용 화면(백필 큐)을 만들고, 앞으로의 협업은 입력이 습관이 되게.

**핵심 판단: 이번 1차 목표는 성과 분석이 아니라 "찾을 수 있는 명부"입니다.** 지표가 없는 상태에서 CPV 대시보드를 먼저 만들면 빈 화면만 봅니다.

## 2. 배경 및 문제

### 지금 상태
- 협업한 인플루언서 **500명 이상**, 자료는 **구글 스프레드시트**
- 릴스 링크는 모아뒀지만 **조회수·좋아요 같은 성과 수치는 거의 없음**
- 단가를 매번 다시 물어본다. 과거에 얼마였는지 추적 불가
- "이 카테고리에서 예산 300만으로 5명" 같은 요청에 즉답이 안 된다

### 진단
문제는 "기록이 없다"가 아니라 **"기록이 찾을 수 있고 비교할 수 있는 형태가 아니다"** 입니다.

### 시트로 계속 못 가는 이유
| 한계 | 왜 문제인가 |
|---|---|
| 행 500개 넘으면 스크롤 지옥 | 조건 조합 검색이 사실상 불가 |
| 단가는 값이 하나만 들어간다 | "2024년 80만 → 2026년 150만"이 안 남음. 덮어쓰면 이력이 사라짐 |
| 이미지·스크린샷을 못 담는다 | 인사이트 증빙이 시트 밖 폴더에 흩어짐 |
| 계산 컬럼이 깨진다 | CPV·참여율을 수식으로 넣으면 행 추가·복붙에서 무너짐 |
| 링크가 죽어도 모른다 | 게시물 삭제 감지 불가 |

**단, 시트를 버리진 않습니다.** 시트는 최초 이관 소스이자 백업 내보내기 형식으로 유지합니다.

## 4. 목표와 범위

### 목표
1. 500명 명부에서 조건 조합으로 **10초 안에** 후보를 찾는다
2. 인플루언서 1명 = 페이지 1개. 프로필·단가 이력·협업 이력·릴스 링크가 한 화면
3. 성과 수치를 **건당 20초 안에** 입력할 수 있다 (이 마찰이 프로젝트 성패를 가른다)
4. 지표가 쌓이면 CPV·뷰배수로 정렬해 재협업 판단 근거가 된다

### 하지 않을 것
- 인플루언서 발굴/검색(디스커버리) — 우리가 아는 사람만 관리
- 인스타 스크래핑·크롤링 — 약관 리스크 + 금방 깨짐
- 계약서 생성, 전자서명, 세금계산서 발행
- 인플루언서와의 메시지 기능 — DM·메일은 기존 채널 유지
- 실시간 지표 동기화

## 5. 핵심 전략 — 성과를 어떻게 쌓을 것인가

500명의 링크는 있는데 수치가 없는 상황에서, 가장 중요한 기능은 대시보드가 아니라 **입력 마찰 제거**입니다.

### 5.1 성과 백필 큐 (Phase 2의 중심 기능)

수치가 비어 있는 콘텐츠만 한 줄씩 띄워주는 전용 화면입니다.

```
[릴스 썸네일]  @handle · 2025-03-12 · A브랜드
링크 열기 ↗   조회수 [        ]  좋아요 [        ]  댓글 [        ]
                              [건너뛰기]  [저장하고 다음 →]
```

- 링크를 새 탭에서 열고, 공개로 보이는 3개 숫자만 입력 → Enter → 다음 건
- 500건이라도 하루 이틀 작업으로 끝나게 설계
- 진행률 표시 ("412건 중 178건 완료")
- 인사이트 스크린샷이 있는 건은 저장·공유·도달까지 추가 입력 (선택)

**이 화면 하나가 이 프로젝트에서 가장 ROI가 높습니다.** 여기서 채워진 데이터가 이후 모든 지표의 재료입니다.

### 5.2 앞으로의 협업은 입력이 습관이 되게
- 협업 등록 시 업로드 예정일 기록 → 업로드 후 3일/30일에 **입력 리마인더**
- 대시보드에 "성과 미입력 N건" 상시 노출
- 필수 필드는 4개 이하로 유지

## 6. 사용 시나리오

### 시나리오 A — 후보 뽑기 (가장 자주)
1. 명부에서 필터: 카테고리=뷰티, 팔로워 3만~10만, 최신 단가 ≤120만, 재협업 의향=무조건
2. 12명 → 다중 선택 → 후보 리스트에 담기
3. 예산 합계 확인 → 공유용으로 내보내기

### 시나리오 B — 협업 직후 기록
1. 인플루언서 검색 → 협업 추가 (캠페인, 확정 단가, 제공 제품)
2. 릴스 URL 붙이기 → 3일 후 리마인더 → 수치 입력
3. CPV·뷰배수 자동 계산, 등급 자동 부여

### 시나리오 C — 재협업 판단
1. 인플루언서 상세 → 과거 3건 CPV 추이 + 단가 인상 시점 겹쳐보기
2. "단가는 2배 올랐는데 뷰배수는 절반" → 조건부로 재협상

### 시나리오 D — 단가 문의 대응
이름 검색 → 최신 유효 단가 카드 확인 (30초)

### 7.2 단가 `rate_card` — 인플루언서 : N (시점별 이력)

단가는 숫자 하나가 아니라 **항목 × 시점**입니다. 인플루언서 테이블 컬럼으로 넣으면 반드시 후회합니다.

| 필드 | 설명 | 단계 |
|---|---|:--:|
| `deliverable_type` | 릴스 / 릴스+스토리 / 스토리단독 / 피드 / 쇼츠 / 라이브 / 방문형 | 1차 |
| `amount` | 금액 (KRW) | 1차 |
| `vat_included` | 부가세 포함 여부 — **누락 시 분쟁 1순위** | 1차 |
| `price_kind` | 제시가(본인) / 제안가(우리) / 최종합의가 | 1차 |
| `barter_type` | 현금 / 제품제공 / 현금+제품 | 1차 |
| `barter_value` | 제공 제품 정가 → 실질 비용 계산 | 2차 |
| `valid_from` / `valid_until` | **유효기간. 이게 있어야 "최신 단가"를 뽑을 수 있다** | 1차 |
| `usage_rights` | 없음 / 2차활용(광고소재) / 기간한정 / 무기한 | 2차 |
| `exclusivity_days` | 경쟁사 배제 기간 | 2차 |

→ 상세 화면은 `valid_from` 최신 + `최종합의가` 우선으로 "현재 단가"를 보여주고, 나머지는 이력으로 접어둡니다.

### 7.6 성과 스냅샷 `content_metric` — 콘텐츠 : N

릴스는 업로드 후 2~4주까지 조회수가 계속 오릅니다. 단일 값으로 저장하면 **24시간 뒤 기록한 A와 한 달 뒤 기록한 B를 공정하게 비교할 수 없습니다.** 그래서 스냅샷으로 분리합니다.

| 필드 | 설명 | 단계 |

| `measured_at` | 측정 시점 | 1차 |

## 8. 지표 정의

파생 지표는 **컬럼으로 저장하지 않고 DB view로 계산**합니다. 기준이 바뀌면 전체가 재계산되어야 하기 때문입니다.

| 지표 | 공식 | 의미 |
|---|---|---|
| **뷰 배수** | `views / follower_count` | **릴스 평가의 핵심.** 1배 미만이면 팔로워에게만 도달(확산 실패), 3배 이상이면 알고리즘을 탔다는 뜻 |
| **CPV** | `total_cost / views` | 가장 직관적인 가성비 (원/뷰) |
| CPE | `total_cost / (likes+comments+saves+shares)` | 인터랙션 기준 효율 |
| CPM | `total_cost / views × 1000` | 광고 대비 벤치마크 |
| 참여율 | `(likes+comments) / views` | 도달 데이터 있으면 도달 기준이 더 정확 |
| 저장률 | `saves / views` | 정보성 콘텐츠 품질 |
| 공유율 | `shares / views` | 바이럴 잠재력 |
| 인플루언서 대표값 | 위 지표들의 **중앙값** | 평균은 대박 1건에 왜곡됨 |
| 등급 | A / B / C / D | 뷰배수 + CPV 백분위 조합. 기준은 설정에서 조정 가능 |

**팔로워 대비 뷰 배수를 1차 정렬 기준으로 권장합니다.** 조회수 절대값은 팔로워 많은 사람이 무조건 이기지만, 뷰 배수는 "이 사람 콘텐츠가 실제로 퍼지는가"를 봅니다. 마이크로 인플루언서의 가성비가 여기서 드러납니다.

## 9. 화면 구성

### 9.1 명부 (메인) — Phase 1
500명을 다루는 화면이라 가장 공들여야 합니다.

- **테이블 뷰**: 썸네일 · 이름/핸들 · 팔로워 · 티어 · 카테고리 · 최신 단가 · 협업수 · 뷰배수 · CPV · 재협업 의향 · 상태
- **갤러리 뷰**: 카드형 (제안 자료 만들 때)
- **필터**: 카테고리, 태그, 팔로워 범위, 단가 범위, 재협업 의향, 상태, 지역, 소속사 유무, 협업 유무, 지표 유무
- **저장된 뷰**: "뷰티 마이크로 가성비" 같은 조합을 재사용
- **벌크 편집**: 여러 명 선택 → 태그 일괄 추가, 상태 일괄 변경 (500명 정리에 필수)
- 다중 선택 → 후보 리스트 담기 / 비교 / CSV 내보내기

### 9.2 인플루언서 상세 — Phase 1
- 헤더: 아바타, 이름, 핸들+원본링크, 팔로워, 티어, 카테고리 칩, 상태, 재협업 의향
- 요약: 협업 N회, 총 지출, 누적 조회수, 중앙 CPV, 중앙 뷰배수
- **단가 카드**: 현재 유효 단가 + 이력 타임라인(접기)
- **협업 히스토리**: 캠페인별 카드 → 릴스 썸네일 + 지표 + 원본 링크
- **성과 추이**: 협업 시점별 CPV·뷰배수 (단가 인상 시점 표시) + 팔로워 추이
- 컨택 정보 (권한별 마스킹) / 내부 메모 / 첨부파일

### 9.3 성과 백필 큐 — Phase 2
5.1 참조. 이 프로젝트의 승부처.

### 9.4 콘텐츠 성과 목록 — Phase 2
> 릴스 성과를 인플루언서 무관하게 한 테이블에서 보는 화면

- 썸네일 · 인플루언서 · 캠페인 · 게시일 · 조회수 · 좋아요 · 저장 · 참여율 · 뷰배수 · 비용 · CPV · 등급 · 원본 링크
- 인사이트 스크린샷 라이트박스
- **성과 분포 산점도**: X=팔로워, Y=조회수, 대각선에 1배·3배 기준선 → 저평가된 인플루언서를 눈으로 찾는 뷰

### 9.5 대시보드 — Phase 3
- KPI: 총 인플루언서 / 총 협업 / 누적 지출 / 누적 조회수 / 평균 CPV
- 카테고리별 평균 CPV 막대
- **입력 누락 알림**: "성과 미입력 12건", "업로드 30일 지났는데 최종 스냅샷 없음 5건" ← 데이터가 썩는 걸 막는 장치

### 9.6 후보 리스트 & 공유 — Phase 3
- 담기 → 예산 합계(부가세 옵션) / 예상 총 도달 / 예상 CPV
- 공유 링크 옵션: **단가 숨김 / 그대로 / 마크업 % 적용**, 만료일, 비밀번호
- 공유 페이지는 읽기 전용, **내부 메모·컨택·평점은 절대 미노출**

### 9.7 비교 뷰 — Phase 3
최대 5명 나란히: 팔로워, 단가, 협업수, CPV, 뷰배수, 참여율, 평점, 대표 콘텐츠 3건. 지표별 최고값 하이라이트

### 9.8 입력
- **빠른 등록**: 이름·핸들·플랫폼·팔로워 4개만으로 생성
- **CSV 임포트**: 컬럼 매핑 UI + 프리뷰 + 핸들 기준 중복 병합/스킵
- 인스타 URL 붙이면 oEmbed로 썸네일·캡션 보조 채우기 (지표는 수동)

## 10. 개발 로드맵

| 단계 | 기간 | 내용 | 완료 시점의 상태 |
|---|---|---|---|
| **Phase 0** 데이터 이관 | 1주 | 시트 컬럼 구조 확인 → 스키마 확정 → Supabase 구축 → CSV 임포터 → 500명 이관 및 정제(중복 핸들, 표기 통일) | 500명이 DB에 들어감 |
| **Phase 1** 명부 | 2주 | 로그인 · 명부 테이블 · 검색/필터/저장된 뷰 · 벌크 편집 · 상세 페이지 · 단가 이력 · 빠른 등록 | **실사용 시작.** 시트를 닫아도 됨 |
| **Phase 2** 성과 쌓기 | 1.5주 | 성과 백필 큐 · 콘텐츠 성과 목록 · 파생지표 view · 스냅샷 · 스크린샷 업로드 | 지표가 채워지기 시작 |
| **Phase 3** 의사결정 | 1.5주 | 대시보드 · 후보 리스트 · 공유 링크 · 비교 뷰 · 차트 · 산점도 | 제안·판단 도구로 완성 |
| **Phase 4** 운영 | 이후 | 입력 리마인더 · 등급 기준 커스터마이즈 · 팔로워 자동 스냅샷 · 유튜브/틱톡 · 팀 초대 | |

**Phase 0을 UI보다 먼저 하는 이유:** 실제 500명 데이터를 넣어보면 필드가 반드시 바뀝니다. 화면부터 만들면 두 번 만들게 됩니다.

### 기술 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 프론트 | Next.js App Router + TypeScript | 500행 필터링을 서버에서 처리 |
| UI | Tailwind + shadcn/ui | 테이블·필터·다이얼로그가 화면의 대부분 |
| 테이블 | TanStack Table | 정렬·필터·컬럼 토글·가상 스크롤 |
| 차트 | Recharts | 추이선·막대·산점도 수준이면 충분 |
| DB / 인증 / 파일 | Supabase | Postgres view로 지표 계산, RLS로 권한, Storage로 스크린샷 |
| 배포 | Vercel | |

### 설계 원칙 3가지
1. **파생 지표는 컬럼으로 저장하지 않는다.** view 또는 계산 필드로. 기준이 바뀌면 재계산돼야 한다
2. **시간에 따라 변하는 값은 전부 이력 테이블.** 단가·팔로워·성과. 덮어쓰기 금지
3. **입력 마찰을 최소화한다.** 필수 필드 4개 이하. 안 쓰이는 툴이 되는 원인의 90%는 입력이 귀찮아서다

## 11. 권한 및 보안

| 역할 | 권한 |
|---|---|
| owner | 전체 + 설정 + 멤버 관리 + 삭제 |
| editor | 조회 + 등록/수정, 단가·컨택 조회 가능 |
| viewer | 조회만. 컨택 마스킹, 내부 메모 비노출 |
| 공유 링크 | 지정된 후보 리스트만. 단가 정책 적용, 메모·컨택·평점 전부 비노출 |

- 연락처·실명은 **컬럼 단위 암호화**, viewer에게 마스킹
- **계좌번호는 저장하지 않음**
- 인스타 스크래핑 없음. 공개 임베드(oEmbed)와 수동 입력만
- 이미지는 자체 스토리지에 업로드 보관 (인스타 CDN 링크는 만료됨)
- 모든 지표에 `source` 표기 — 본인이 전달한 수치와 스크린샷 확인 수치를 시각적으로 구분
- 소프트 삭제, 변경 이력, 일일 백업 + **CSV 전체 내보내기** (락인 방지)

## 13. 다음 확인 사항

**Phase 0 착수 전에 필요합니다**

1. **스프레드시트 컬럼 구조** — 시트를 공유해주시거나 헤더 행만 캡처해주세요. 현재 컬럼에 맞춰 스키마와 임포터를 확정하겠습니다. 여기서 Phase 0 작업량이 갈립니다.
2. **500명 중 실제 협업까지 간 사람은 몇 명인가요?** 컨택만 하고 끝난 사람이 다수라면, 명부를 "협업 완료 / 컨택 이력"으로 나눠서 기본 필터를 잡겠습니다.
3. **릴스 링크는 몇 건 정도 모여 있나요?** 백필 큐의 작업량 산정에 필요합니다.

**있으면 좋습니다**

4. 단가에 물물교환(제품 제공)이 섞인 비중이 큰가요? 제품 정가를 비용에 포함해 CPV를 계산할지 결정해야 합니다.
5. 캠페인/브랜드 단위 묶음이 의미가 있나요? 의미가 없으면 `campaign` 테이블을 태그로 단순화하겠습니다.
6. 여러 명이 같이 입력하나요, 혼자 쓰나요? 혼자면 권한 시스템을 Phase 4로 미루겠습니다.
7. 유튜브·틱톡 협업도 있나요, 인스타만인가요?
8. 프로모 코드나 UTM으로 **매출 전환**을 추적한 적이 있나요? 있으면 ROAS를 지표에 넣겠습니다.
