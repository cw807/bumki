## 1. 한 장 요약

500명 넘게 쌓인 릴스 협업 이력이 구글 스프레드시트에 흩어져 있고, **성과 수치는 거의 기록되지 않은 상태**입니다.

이 프로젝트는 두 가지를 순서대로 해결합니다.

1. **먼저 명부를 세운다** — 500명을 검색·필터·태그로 즉시 찾을 수 있게. 단가는 시점별 이력으로.
2. **그 다음 성과를 쌓는다** — 링크만 있는 과거 협업의 공개 수치를 빠르게 채워 넣는 전용 화면(백필 큐)을 만들고, 앞으로의 협업은 입력이 습관이 되게.

**핵심 판단: 이번 1차 목표는 성과 분석이 아니라 "찾을 수 있는 명부"입니다.** 지표가 없는 상태에서 CPV 대시보드를 먼저 만들면 빈 화면만 봅니다.

## 2. 배경 및 문제

### 지금 상태
- 협업한 인플루언서 **500명 이상**, 자료는 **구글 스프레드시트**
- 릴스 링크는 모아뒀지만 **조회수·좋아요 같은 성과 수치는 거의 없음**
- 단가를 매번 다시 물어본다. 과거에 얼마였는지 추적 불가
- "이 카테고리에서 예산 300만으로 5명" 같은 요청에 즉답이 안 된다

### 진단
문제는 "기록이 없다"가 아니라 **"기록이 찾을 수 있고 비교할 수 있는 형태가 아니다"** 입니다.

### 시트로 계속 못 가는 이유
| 한계 | 왜 문제인가 |
|---|---|
| 행 500개 넘으면 스크롤 지옥 | 조건 조합 검색이 사실상 불가 |
| 단가는 값이 하나만 들어간다 | "2024년 80만 → 2026년 150만"이 안 남음. 덮어쓰면 이력이 사라짐 |
| 이미지·스크린샷을 못 담는다 | 인사이트 증빙이 시트 밖 폴더에 흩어짐 |
| 계산 컬럼이 깨진다 | CPV·참여율을 수식으로 넣으면 행 추가·복붙에서 무너짐 |
| 링크가 죽어도 모른다 | 게시물 삭제 감지 불가 |

**단, 시트를 버리진 않습니다.** 시트는 최초 이관 소스이자 백업 내보내기 형식으로 유지합니다.

### 3.1 확인된 실제 시트 구조

두 계열로 나뉘고, **컬럼명·구조가 서로 다릅니다.** 통합 파서 하나로는 안 되고 시트별 어댑터가 필요합니다.

**키뮤어 계열** — 예: `[26 FALL / MU] kiimuir 콘텐츠 협업(응답)`, 33행

```
타임스탬프 | 업로드 콘텐츠(이미지 피드/릴스) | 인스타그램 아이디 | 나이/키/몸무게
| 성함 | 연락처 | 우편번호 | 상세주소 | 협찬 희망 제품 | 2차 활용 동의 | 폴더링/특이사항
```

**코드그라피 계열** — 예: `CGP 26 Summer : 인스타그램 릴스 (토마토/6Style)(응답)`, 18행

```
출고상태 | 타임스탬프 | 인스타그램 아이디 | 이름 | 연락처 | 우편번호 | 주소 | 키
| 제품 선택 | 영상 전달 일정 | (색상 / 사이즈 / 동의) × 제품 6세트 반복
+ 시트 하단에 제품코드 ↔ 제품명 매핑표
```

**여기서 도출되는 제약**

| 발견 | 영향 |
|---|---|
| **단가 컬럼이 없다** | 전부 제품 시딩. 비용 모델을 현금 단가 → 제품 원가로 전환 |
| **게시물 URL 컬럼이 없다** | 성과 백필의 최대 난관. 5.1 자동 매칭 전략으로 대응 |
| 컬럼명 불일치 (`성함`/`이름`, 신체정보 1칸/분리) | 시트별 어댑터 + 매핑 UI 필수 |
| 제품 선택이 6세트 반복 컬럼 | 정규화해서 `collab_product` 행으로 펼쳐야 함 |
| 핸들 표기 불일치 (`@seucinnam` / `seucinnam`) | 정규화 후 병합 |
| 동일인 중복 응답 | 한 시트 안에서도 3회 등장(`__hhhsh_` 7/28·7/30·8/10) → 인물 1명 + 협업 N건으로 분리 |
| 나이·키·몸무게·전체 주소 수집 | 배송·착장 목적. 사이트 이관 시 목적 범위 초과 주의 → 7.1 참조 |

## 4. 목표와 범위

### 목표
1. 500명 명부에서 조건 조합으로 **10초 안에** 후보를 찾는다
2. 인플루언서 1명 = 페이지 1개. 프로필·단가 이력·협업 이력·릴스 링크가 한 화면
3. 성과 수치를 **건당 20초 안에** 입력할 수 있다 (이 마찰이 프로젝트 성패를 가른다)
4. 지표가 쌓이면 CPV·뷰배수로 정렬해 재협업 판단 근거가 된다

### 하지 않을 것
- 인플루언서 발굴/검색(디스커버리) — 우리가 아는 사람만 관리
- 인스타 스크래핑·크롤링 — 약관 리스크 + 금방 깨짐
- 계약서 생성, 전자서명, 세금계산서 발행
- 인플루언서와의 메시지 기능 — DM·메일은 기존 채널 유지
- 실시간 지표 동기화

## 5. 핵심 전략 — 성과를 어떻게 쌓을 것인가

응답 시트에는 **게시물 URL 자체가 없습니다.** 즉 문제는 "수치가 없다"가 아니라 "링크부터 없다"입니다. 그래서 전략이 2단이 됩니다.

### 5.1 링크 자동 매칭 (선행 단계)

응답 시트에 핸들과 타임스탬프는 전부 있습니다. 이 두 개로 게시물을 역추적합니다.

```
응답 시트의 핸들 + 타임스탬프
  → Apify로 해당 계정의 릴스·피드 수집 (타임스탬프 기준 +2~4주 윈도우)
  → 캡션에 브랜드 멘션(@kiimuir / @codegraphy) 또는 paidPartnership 플래그
  → 해당 협업 건에 자동 매칭 → 사람은 검수만
```

- 매칭 신뢰도를 3단계로 표기: 확실(멘션+기간 일치) / 추정(기간만 일치) / 실패
- 실패 건만 수동 입력 큐로 넘김 — 500건을 손으로 모으는 것보다 훨씬 적은 작업
- 브랜드 계정에 태그된 게시물을 역방향으로 긁는 경로도 보조로 사용

**한계:** 100% 매칭은 불가능합니다. 협업자가 멘션을 안 했거나 이미 삭제한 건은 놓칩니다. 그래서 **앞으로의 협업은 폼에 "업로드 링크" 컬럼을 추가하는 것이 근본 해결책**입니다 (5.3).

### 5.2 성과 백필 큐

링크가 확보된 콘텐츠 중 수치가 비어 있는 것만 한 줄씩 띄워주는 전용 화면입니다. Apify로 조회수·좋아요·댓글은 자동 수집되므로, 이 화면은 **인사이트 스크린샷이 있는 건의 도달·저장·공유를 채우는 용도**가 주가 됩니다.

```
[릴스 썸네일]  @handle · 2025-03-12 · A브랜드
링크 열기 ↗   조회수 [        ]  좋아요 [        ]  댓글 [        ]
                              [건너뛰기]  [저장하고 다음 →]
```

- 링크를 새 탭에서 열고 숫자만 입력 → Enter → 다음 건
- 진행률 표시 ("412건 중 178건 완료")
- Apify가 채운 값은 미리 채워진 상태로 보여주고, 사람은 이상값만 고침

### 5.3 앞으로의 협업은 입력이 습관이 되게

**폼을 먼저 고치는 것이 가장 값싼 개선입니다.** 응답 시트에 다음 컬럼을 추가하면 이후 협업은 백필이 아예 필요 없어집니다.

| 추가할 폼 항목 | 이유 |
|---|---|
| **업로드 게시물 링크** | 지금 가장 큰 공백. 이것만 받으면 링크 매칭 로직이 불필요해짐 |
| 업로드 완료일 | 스냅샷 기준일 |
| 인사이트 스크린샷 업로드 | 도달·저장·공유 확보 |

- 협업 등록 시 업로드 예정일 기록 → 업로드 후 3일/30일에 **입력 리마인더**
- 대시보드에 "성과 미입력 N건" 상시 노출
- 필수 필드는 4개 이하로 유지

## 6. 사용 시나리오

### 시나리오 A — 후보 뽑기 (가장 자주)
1. 명부에서 필터: 카테고리=뷰티, 팔로워 3만~10만, 최신 단가 ≤120만, 재협업 의향=무조건
2. 12명 → 다중 선택 → 후보 리스트에 담기
3. 예산 합계 확인 → 공유용으로 내보내기

### 시나리오 B — 협업 직후 기록
1. 인플루언서 검색 → 협업 추가 (캠페인, 확정 단가, 제공 제품)
2. 릴스 URL 붙이기 → 3일 후 리마인더 → 수치 입력
3. CPV·뷰배수 자동 계산, 등급 자동 부여

### 시나리오 C — 재협업 판단
1. 인플루언서 상세 → 과거 3건 CPV 추이 + 단가 인상 시점 겹쳐보기
2. "단가는 2배 올랐는데 뷰배수는 절반" → 조건부로 재협상

### 시나리오 D — 단가 문의 대응
이름 검색 → 최신 유효 단가 카드 확인 (30초)

| `real_name` | 실명 — 민감정보, 암호화 | 2차 |
| `region` | 지역. 방문형 협업 판단용 | 2차 |
| `gender` / `age_range` | | 2차 |
| `height_range` / `size` | 응답 시트의 키·몸무게를 **범위값으로만** 저장 (예: 175~180, 상의 L). 착장 판단에 필요한 최소한 | 2차 |
| ~~정확한 키·몸무게·나이~~ | **원본 그대로 저장하지 않음.** 배송·착장 목적으로 수집된 정보라 아카이브로 옮기면 목적 범위를 넘는다 | 제외 |
| ~~상세 주소~~ | **저장하지 않음.** 배송 목적 한정. 필요 시 지역(시/도)만 | 제외 |

### 7.2 단가 `rate_card` — 인플루언서 : N (시점별 이력)

> **현재 데이터에는 단가가 없습니다.** 응답 시트가 전부 제품 시딩 구조라 현금 단가 컬럼이 존재하지 않습니다. 그래도 이 테이블은 1차에 넣습니다 — 유가 협업으로 전환하거나 상대가 단가를 제시할 때 기록할 곳이 필요하고, 나중에 붙이면 이력이 소급되지 않기 때문입니다. 초기에는 대부분 `barter_type = 제품제공`으로 채워집니다.

단가는 숫자 하나가 아니라 **항목 × 시점**입니다. 인플루언서 테이블 컬럼으로 넣으면 반드시 후회합니다.

| 필드 | 설명 | 단계 |
|---|---|:--:|
| `deliverable_type` | 릴스 / 릴스+스토리 / 스토리단독 / 피드 / 쇼츠 / 라이브 / 방문형 | 1차 |
| `amount` | 금액 (KRW) | 1차 |
| `vat_included` | 부가세 포함 여부 — **누락 시 분쟁 1순위** | 1차 |
| `price_kind` | 제시가(본인) / 제안가(우리) / 최종합의가 | 1차 |
| `barter_type` | 현금 / 제품제공 / 현금+제품 | 1차 |
| `barter_value` | 제공 제품 정가 → 실질 비용 계산 | 2차 |
| `valid_from` / `valid_until` | **유효기간. 이게 있어야 "최신 단가"를 뽑을 수 있다** | 1차 |
| `usage_rights` | 없음 / 2차활용(광고소재) / 기간한정 / 무기한 | 2차 |
| `exclusivity_days` | 경쟁사 배제 기간 | 2차 |
| `revision_limit` | 수정 횟수 | 선택 |
| `source_note` | "2026-03 DM에서 제시" 같은 출처 | 2차 |

→ 상세 화면은 `valid_from` 최신 + `최종합의가` 우선으로 "현재 단가"를 보여주고, 나머지는 이력으로 접어둡니다.

## 8. 지표 정의

파생 지표는 **컬럼으로 저장하지 않고 DB view로 계산**합니다. 기준이 바뀌면 전체가 재계산되어야 하기 때문입니다.

| 지표 | 공식 | 의미 |
|---|---|---|
| **뷰 배수** | `views / follower_count` | **릴스 평가의 핵심.** 1배 미만이면 팔로워에게만 도달(확산 실패), 3배 이상이면 알고리즘을 탔다는 뜻 |
| **CPV** | `total_cost / views` | 가장 직관적인 가성비 (원/뷰). **현재 데이터에서는 분자가 제공 제품 원가** |
| CPE | `total_cost / (likes+comments+saves+shares)` | 인터랙션 기준 효율 |
| CPM | `total_cost / views × 1000` | 광고 대비 벤치마크 |
| 참여율 | `(likes+comments) / views` | 도달 데이터 있으면 도달 기준이 더 정확 |
| 저장률 | `saves / views` | 정보성 콘텐츠 품질 |
| 공유율 | `shares / views` | 바이럴 잠재력 |
| 인플루언서 대표값 | 위 지표들의 **중앙값** | 평균은 대박 1건에 왜곡됨 |
| 등급 | A / B / C / D | 뷰배수 + CPV 백분위 조합. 기준은 설정에서 조정 가능 |

**팔로워 대비 뷰 배수를 1차 정렬 기준으로 권장합니다.** 조회수 절대값은 팔로워 많은 사람이 무조건 이기지만, 뷰 배수는 "이 사람 콘텐츠가 실제로 퍼지는가"를 봅니다. 마이크로 인플루언서의 가성비가 여기서 드러납니다.

## 11. 권한 및 보안

| 역할 | 권한 |
|---|---|
| owner | 전체 + 설정 + 멤버 관리 + 삭제 |
| editor | 조회 + 등록/수정, 단가·컨택 조회 가능 |
| viewer | 조회만. 컨택 마스킹, 내부 메모 비노출 |
| 공유 링크 | 지정된 후보 리스트만. 단가 정책 적용, 메모·컨택·평점 전부 비노출 |

- 연락처·실명은 **컬럼 단위 암호화**, viewer에게 마스킹
- **계좌번호·상세주소·정확한 신체정보는 저장하지 않음.** 응답 시트에는 있지만 배송·착장 목적으로 수집된 것이라, 아카이브로 옮기면 수집 목적을 넘어선다. 필요한 만큼만(지역, 사이즈 범위) 가공해서 저장
- 공유 링크에는 개인정보를 일절 포함하지 않음
- **Apify 사용 범위를 아카이브 대상으로 한정.** 우리가 협업한 계정의 공개 게시물만 조회하고, 무제한 크롤링은 하지 않음. 스크래핑은 플랫폼 약관 이슈가 있으므로 수집 항목을 최소화한다
- 이미지는 자체 스토리지에 업로드 보관 (인스타 CDN 링크는 만료됨)
- 모든 지표에 `source` 표기 — 본인이 전달한 수치와 스크린샷 확인 수치를 시각적으로 구분
- 소프트 삭제, 변경 이력, 일일 백업 + **CSV 전체 내보내기** (락인 방지)

## 13. 다음 확인 사항

**Phase 0 착수 전에 필요합니다**

1. **대상 시트 목록 확정** — 드라이브에서 응답 시트 25개 이상을 찾았습니다(키뮤어 14+, 코드그라피 10+, 드림크루 등). 이 전부를 넣을까요, 특정 시즌 이후만 넣을까요? 그리고 제가 못 본 시트가 더 있나요? `시딩 데이터 test`는 빈 시트였습니다.
2. **게시물 링크를 어디서 관리하시나요?** `폴더링` 컬럼과 `[사진제출]` 시트를 보면 드라이브 폴더로 관리하시는 것 같습니다. 폴더 구조를 알려주시면 링크·파일도 같이 이관하겠습니다. 링크가 아예 없다면 Apify 자동 매칭(5.1)으로 가고, 실패분만 수동 입력합니다.
3. **제품 원가를 쓸 수 있나요?** CPV의 분자가 제품 원가라서 필요합니다. 정가로 계산할지 원가로 계산할지, 그리고 제품코드↔가격 표를 받을 수 있는지요. (CGP 시트 하단에 제품코드 매핑표는 이미 있었습니다)
4. **Apify 플랜** — 현재 `릴스크리에이터` 자동화에서 402(`actor-memory-limit-exceeded`, 16GB 한도)가 반복되고 있습니다. 500명 백필은 더 큰 작업이라 플랜 상향 또는 배치 분산이 필요합니다. 예산 범위를 알려주세요.

**있으면 좋습니다**

5. 폼에 **업로드 링크 컬럼을 추가**할 수 있나요? 5.3 참고 — 앞으로의 협업에서 백필을 없애는 가장 값싼 방법입니다.
6. 유가(현금) 협업도 있나요? 있으면 단가 데이터를 어디서 가져올지 알려주세요. 없으면 `rate_card`는 빈 상태로 두고 시딩 원가만 씁니다.
7. 브랜드가 키뮤어·코드그라피 둘인가요, 더 있나요? 캠페인 파싱 규칙에 반영합니다.
8. 여러 명이 같이 입력하나요, 혼자 쓰나요? 혼자면 권한 시스템을 Phase 4로 미루겠습니다.
9. `릴스크리에이터` 발굴 자동화와 이 사이트를 붙일까요? 발굴 후보 → 아카이브 등록 → 성과 → 발굴 기준 보정으로 순환됩니다. 참고로 현재 발굴 쪽은 추천 0명입니다(`MIN_MEDIAN_VIEWS 10000` + `MIN_SCORE 70`이 동시에 걸려 전원 컷).
10. 프로모 코드나 UTM으로 **매출 전환**을 추적한 적이 있나요? 있으면 ROAS를 지표에 넣겠습니다.
